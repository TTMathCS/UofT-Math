Stacks & Queues

Two ADTs that differ in exactly one respect: which end you take from. That single choice changes what an algorithm computes, which is why the same traversal code explores depth-first with one and breadth-first with the other.

By the end you can
  • State the contract for a Stack and a Queue.
  • Implement both with the right end of a Python list.
  • Explain why the naive queue implementation is $O(n)$.
  • Recognise which problems call for which.
Why it matters & where it comes from
Why it exists

Some problems need the most recent item, others the oldest. Naming those two disciplines and giving each a tiny interface makes the intent of an algorithm obvious from which one it uses.

In the real world

The call stack is why a function returns to its caller and why infinite recursion produces a "stack overflow". Print queues, network packet buffers and task schedulers are queues. Undo history is a stack.

Story & open questions

Turing described a stack mechanism for subroutine calls in 1946. Making it the standard way to implement function calls was what allowed recursion to exist as a language feature at all.

Stack

Definition

A stack is last-in-first-out. The only accessible item is the one added most recently. Operations: push, pop, is_empty.

Example Implementation
python
class Stack:
    """A last-in-first-out collection.

    Attributes:
        _items: the contents, with the top of the stack at the end
    """
    _items: list

    def __init__(self) -> None:
        """Initialize an empty stack."""
        self._items = []

    def push(self, item) -> None:
        """Add item to the top of this stack."""
        self._items.append(item)

    def pop(self):
        """Remove and return the top item of this stack.

        Preconditions: this stack is not empty.

        >>> s = Stack()
        >>> s.push(1)
        >>> s.push(2)
        >>> s.pop()
        2
        """
        return self._items.pop()

    def is_empty(self) -> bool:
        """Return whether this stack is empty."""
        return self._items == []
The top is at the end of the list, deliberately. Both append and pop() are $O(1)$ there.
Putting the top at the front would still be correct but $O(n)$ per operation, as Unit 1 showed.
Example Balanced brackets
python
def balanced(text: str) -> bool:
    """Return whether the brackets in text are correctly nested.

    >>> balanced('([])')
    True
    >>> balanced('([)]')
    False
    """
    pairs = {')': '(', ']': '[', '}': '{'}
    s = Stack()
    for ch in text:
        if ch in '([{':
            s.push(ch)
        elif ch in pairs:
            if s.is_empty() or s.pop() != pairs[ch]:
                return False
    return s.is_empty()
A stack is exactly right because the bracket that must close next is always the most recently opened one.
The final is_empty check matters: without it '((' would pass.

Queue

Definition

A queue is first-in-first-out. The only accessible item is the one added earliest. Operations: enqueue, dequeue, is_empty.

Example The obvious implementation, and its flaw
python
class Queue:
    """A first-in-first-out collection.

    Attributes:
        _items: the contents, with the front of the queue at index 0
    """
    _items: list

    def __init__(self) -> None:
        """Initialize an empty queue."""
        self._items = []

    def enqueue(self, item) -> None:
        """Add item to the back of this queue."""
        self._items.append(item)          # O(1)

    def dequeue(self):
        """Remove and return the front item of this queue.

        Preconditions: this queue is not empty.

        >>> q = Queue()
        >>> q.enqueue(1)
        >>> q.enqueue(2)
        >>> q.dequeue()
        1
        """
        return self._items.pop(0)         # O(n) - shifts everything
This is correct but asymmetric: enqueue is $O(1)$ and dequeue is $O(n)$, because removing index $0$ shifts every remaining element down.
A queue cannot avoid this with one Python list, since it needs both ends. Unit 4's linked list fixes it by keeping a reference to each end, making both $O(1)$.
In production you would use collections.deque, which is $O(1)$ at both ends. Writing it out by hand is the point here.

Why the choice changes the answer

Example The same code, two behaviours

Exploring a structure by taking from a collection and adding neighbours:

python
def explore(start, use_stack: bool) -> list:
    """Return the nodes reachable from start, in visit order.

    With use_stack the exploration is depth-first; otherwise
    it is breadth-first.
    """
    pending = Stack() if use_stack else Queue()
    add = pending.push if use_stack else pending.enqueue
    take = pending.pop if use_stack else pending.dequeue

    add(start)
    seen = []
    while not pending.is_empty():
        node = take()
        if node not in seen:
            seen.append(node)
            for neighbour in node.neighbours:
                add(neighbour)
    return seen
With a stack, the most recently discovered node is explored next, so the search plunges down one branch before backtracking — depth-first.
With a queue, the earliest discovered node goes next, so the search fans out level by level — breadth-first, which finds the shortest path.
Identical logic, different structure, genuinely different algorithm. This is the clearest argument in the course for taking ADT choice seriously.
Common pitfalls

• Popping from an empty stack or queue. Check the precondition or the emptiness first.
• Using pop(0) in a loop over a large queue and wondering why it is slow.
• Putting the stack top at index $0$. Correct but needlessly $O(n)$.
• Forgetting the final emptiness check in bracket matching.
• Choosing a stack when the problem wants oldest-first. The code runs and the answer is wrong.

Practice

Practice 1 · Order out

Push $1$, $2$, $3$ onto a stack, then pop three times. What comes out?

Answer
$3$, $2$, $1$. A queue would give $1$, $2$, $3$.
Practice 2 · Which ADT

A printer serves jobs in the order submitted. Stack or queue?

Answer
Queue — first in, first out.
Practice 3 · Cost

Why is the list-based dequeue $O(n)$?

Answer
pop(0) removes the first element and shifts every remaining one down by one position.
Practice 4 · Brackets

Why does balanced need the final is_empty()?

Answer
To catch unclosed openers. Without it '(((' would return True.
Practice 5 · Reverse with a stack

Reverse a string using only a stack.

Solution
python
def reverse(text: str) -> str:
    """Return text reversed.

    >>> reverse('abc')
    'cba'
    """
    s = Stack()
    for ch in text:
        s.push(ch)
    out = ''
    while not s.is_empty():
        out = out + s.pop()
    return out
Reversal is the defining behaviour of a stack — items come out in the opposite order to going in.
Practice 6 · Two stacks

How would you build a queue from two stacks?

Solution
Push arrivals onto stack A. To dequeue, if stack B is empty, pop everything from A onto B — which reverses the order — then pop from B. Each item moves at most twice, so the cost averages $O(1)$ per operation even though individual dequeues can be $O(n)$.
Practice 7 · Search order

Which structure finds the shortest path in an unweighted graph?

Answer
A queue. Breadth-first search reaches every node at distance $k$ before any at $k+1$, so the first time it reaches the target is by a shortest route.
Practice 8 · Call stack

Why is the mechanism behind function calls a stack?

Answer
Because the function that must resume next is always the most recent caller. Infinite recursion exhausts it, which is exactly the "stack overflow" error.
