Binary Search Trees

Add one rule to a binary tree — everything left is smaller, everything right is larger — and search becomes logarithmic. It is the same halving as binary search, now on a structure that also supports cheap insertion.

By the end you can
  • State the BST property as a representation invariant.
  • Search, insert and delete while preserving it.
  • Explain why an in-order traversal comes out sorted.
  • Say when a BST degrades to $O(n)$ and why.
Why it matters & where it comes from
Why it exists

A sorted list gives $O(\log n)$ search but $O(n)$ insertion. A linked list reverses that. A BST offers $O(\log n)$ for both — when it stays balanced, which is the catch this unit is honest about.

In the real world

Database indexes are tree structures of this family. Python's dict uses hashing instead, which is faster for lookup but cannot give you the keys in order — the thing a BST does for free.

Story & open questions

Binary search trees were described independently by several groups around 1960. The balancing problem was solved within two years by AVL trees, and later by red-black trees, which is what most standard libraries use today.

The property

Definition

A binary search tree is a binary tree where, for every node:

every value in the left subtree is less than the root, and
every value in the right subtree is greater than the root.

This must hold at every node, not just the top — which is the point people most often miss.

Example The class
python
class BST:
    """A binary search tree.

    Attributes:
        _root: the value at this node, or None if empty
        _left: the left subtree
        _right: the right subtree

    Representation invariants:
        - if self._root is None then self._left is None and
          self._right is None
        - every value in self._left is < self._root
        - every value in self._right is > self._root
    """

    def __init__(self, root) -> None:
        """Initialize a BST containing root, or empty if root is None."""
        self._root = root
        if root is None:
            self._left = None
            self._right = None
        else:
            self._left = BST(None)
            self._right = BST(None)

    def is_empty(self) -> bool:
        """Return whether this tree is empty."""
        return self._root is None

Empty subtrees are empty BSTs rather than None. That keeps every recursive call uniform — no branch has to test whether a subtree exists before recursing into it.

The property is not local

Checking only that each node's immediate children are on the right sides is not enough. A value deep in the left subtree that exceeds the root breaks the tree even if every parent-child pair looks fine. The invariant quantifies over every value in the subtree.

Search

Example Halving at every step
python
def __contains__(self, item) -> bool:
    """Return whether item is in this BST.

    >>> t = BST(5)
    >>> t.insert(3)
    >>> 3 in t
    True
    >>> 4 in t
    False
    """
    if self.is_empty():
        return False
    if item == self._root:
        return True
    if item < self._root:
        return item in self._left       # discard the entire right subtree
    return item in self._right          # discard the entire left subtree
Each comparison eliminates a whole subtree. That is the same halving as binary search, and it is the whole reason the ordering rule exists.
The cost is the height of the tree, not its size. For a balanced tree the height is about $\log_2 n$.
Rule In-order gives sorted output

Traverse left subtree, then root, then right subtree, and the values come out in increasing order.

python
def in_order(self) -> list:
    """Return the values of this BST in increasing order.

    >>> t = BST(5)
    >>> t.insert(3)
    >>> t.insert(8)
    >>> t.in_order()
    [3, 5, 8]
    """
    if self.is_empty():
        return []
    return self._left.in_order() + [self._root] + self._right.in_order()

This falls straight out of the invariant: everything left is smaller, everything right is larger, so visiting in that order is sorted.

Insertion

Example Descend to the right empty spot
python
def insert(self, item) -> None:
    """Insert item into this BST, keeping the BST property.

    Does nothing if item is already present.

    >>> t = BST(5)
    >>> t.insert(3)
    >>> 3 in t
    True
    """
    if self.is_empty():
        self._root = item
        self._left = BST(None)
        self._right = BST(None)
    elif item < self._root:
        self._left.insert(item)
    elif item > self._root:
        self._right.insert(item)
    # equal: already present, nothing to do
The new value always becomes a leaf. The search path determines where, so insertion costs the same as a search.
Duplicates are rejected here. Allowing them would need a rule about which side they go on, and the invariant would have to change from strict to non-strict.

Deletion

Rule Three cases, increasing in difficulty
Leaf. Remove it. Nothing else changes.
One child. Replace the node with that child. The ordering still holds, because everything in that subtree was already on the correct side of the parent.
Two children. Replace the value with its in-order predecessor — the largest value in the left subtree — then delete that value from the left subtree. It has at most one child, so this reduces to an easier case.
Example Why the predecessor works

Deleting $5$ from a tree whose left subtree holds $3$ and $4$, right subtree $8$.

The largest value on the left is $4$. Every remaining left value is below it, and every right value is above it, so putting $4$ at the root preserves the invariant exactly.
Any other choice would break the ordering. The successor — smallest on the right — works equally well for the mirror reason.
Example Finding the predecessor
python
def _largest(self):
    """Return the largest value in this non-empty BST.

    Preconditions: this tree is not empty.
    """
    if self._right.is_empty():
        return self._root
    return self._right._largest()

Keep going right until you cannot. The largest value is always the rightmost node, which is immediate from the invariant.

When it degrades

$O(\log n)$ is the balanced case, not a guarantee

Insert $1, 2, 3, 4, 5$ in order into an empty BST. Each value is larger than everything before it, so each goes to the far right and the tree becomes a chain of five nodes — a linked list with extra steps.

Height becomes $n$ rather than $\log_2 n$.
Search, insert and delete all become $O(n)$.

Sorted input is the worst possible input, which is unfortunate because sorted input is common.

Rule Honest complexity
Average case, random insertion order: $O(\log n)$.
Worst case, sorted insertion: $O(n)$.

Self-balancing variants — AVL and red-black trees — restructure on insertion to keep the height logarithmic and give a genuine worst-case guarantee. Those come in later courses; knowing the plain BST does not guarantee it is what matters here.

Common pitfalls

• Checking the BST property only between a node and its immediate children.
• Quoting $O(\log n)$ as though it were guaranteed.
• Getting the two-child deletion wrong by picking an arbitrary replacement.
• Using None for empty subtrees and then needing a null check in every method.
• Forgetting that in-order, not preorder, is the traversal that comes out sorted.

Practice

Write out each answer before opening it. Original exercises written for this guide in the style of the course's weekly work.

Practice 1 · The property

State the BST invariant.

Answer
At every node, all values in the left subtree are less than the root and all values in the right subtree are greater.
Practice 2 · Build one

Insert $5, 3, 8, 1$ into an empty BST. Describe the shape.

Answer
$5$ at the root, $3$ its left child, $8$ its right child, $1$ the left child of $3$. Height $3$.
Practice 3 · Sorted output

Which traversal gives increasing order, and why?

Answer
In-order. Everything left is smaller and everything right is larger, so left-root-right visits in increasing order.
Practice 4 · Worst case

What input makes a BST degrade to $O(n)$?

Answer
Already-sorted input. Every value goes to the same side and the tree becomes a chain.
Practice 5 · Minimum

Write a method returning the smallest value.

Solution
python
def smallest(self):
    """Return the smallest value in this BST.

    Preconditions: this tree is not empty.
    """
    if self._left.is_empty():
        return self._root
    return self._left.smallest()
Keep going left. The mirror of _largest.
Practice 6 · Height

What is the minimum possible height for $15$ values?

Answer
$4$. A perfectly balanced binary tree of height $h$ holds up to $2^h - 1$ values, and $2^4 - 1 = 15$.
Practice 7 · Verify

Why is checking each node against its children insufficient?

Answer
Because a value deep in the left subtree can exceed an ancestor while still being correctly placed relative to its own parent. The invariant is about every value in the subtree, not just the immediate child.
Practice 8 · BST or dictionary

When would you prefer a BST to a Python dictionary?

Answer
When you need the keys in sorted order, or range queries such as "every value between $10$ and $20$". A dictionary is faster for single lookups but has no order to exploit.

Core idea map

An ordering rule turns a tree into a search structure. Every comparison discards a subtree, so the cost is the height. Keeping the height small is a separate problem, and the plain BST does not solve it.

What determines the cost of a BST search?

Guide
The height of the tree, not the number of values.
Extension 2 · Replacement choice

Why the in-order predecessor when deleting a node with two children?

Guide
It is larger than everything remaining on the left and smaller than everything on the right, so the invariant survives. The successor works symmetrically.
Extension 3 · Degradation

What causes the worst case?

Guide
Sorted or nearly sorted insertion order, which produces a chain instead of a tree.
Extension 4 · Versus hashing

What does a BST offer that a hash table does not?

Guide
Order. Sorted traversal, minimum and maximum, and range queries all come free; a hash table has no order at all.
